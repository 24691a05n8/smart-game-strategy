A*

A* Algorithm

f(n) = g(n) + h(n)

✅ Strengths

  • Guaranteed optimal path
  • Efficient with good heuristic
  • Widely used in game development
  • Easy to implement on grids
  • Works in any metric space

❌ Limitations

  • Memory intensive for large grids
  • Heuristic must be admissible
  • Not suitable for AND-OR problems
  • Performance degrades without heuristic

🌍 Real-World Applications

GPS Navigation Robot Pathfinding Game Level Maps Network Routing Logistics
VS
AO*

AO* Algorithm

Cost(AND) = Σ children | Cost(OR) = min

✅ Strengths

  • Handles decomposable problems
  • AND-OR graph flexibility
  • Natural for hierarchical planning
  • Models real-world decision trees
  • Optimal solution graph extraction

❌ Limitations

  • Complex graph construction
  • Not for simple path problems
  • Requires domain knowledge
  • Harder to implement correctly

🌍 Real-World Applications

Game Tree Search Medical Diagnosis Theorem Proving Robot Assembly Planning Systems

⚡ Performance Analysis

Time Complexity (A*)
O(bd)
b = branching factor, d = depth. Worst case is exponential but typical performance is much better with a good heuristic.
Time Complexity (AO*)
O(V + E)
V = vertices, E = edges in AND-OR graph. Linear in graph size per iteration of the algorithm.
Space Complexity (A*)
O(bd)
Stores all generated nodes in memory. This is the main limitation of A* for very large search spaces.
Space Complexity (AO*)
O(V + E)
Only stores the AND-OR graph structure. More memory efficient for hierarchical problems.
